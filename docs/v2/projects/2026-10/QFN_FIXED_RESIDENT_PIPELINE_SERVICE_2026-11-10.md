# Fixed resident n-gram ranges in the native QFN pipeline

Q7 is an explicit full-VRAM fixed-head placement across all eight observed MI50 devices in `PP(EP4, EP4)`. QFN's authenticated configuration names one main PLE decoder layer. The normal QFN profile places that layer in the first domain. Its four actual DGO participants consume PLE output. The four later participants own fixed native row ranges and serve the one PLE operation inside their own captured forward parent. Their expert and pipeline placement stays unchanged.

## Layout, traffic and arithmetic

Use a single typed projection of the existing resolved stage roster, original model PLE layer and original head offsets. It names the original storage owners and the PLE consumers separately. The ranges cover the exact full table once, including leading, inter-head and trailing gaps. Q7 has two source heads per physical owner and a four-head contribution from each PLE consumer. Derive the owner-to-consumer assignment from actual stage-local coordinates and the original prepared full-pipeline membership. The Q7 pairing below is an example, not a degree constraint: support arbitrary valid original stage counts and widths using explicit head intervals and incident edges. Uneven contributions require compact counted gather on the actual consumer cohort. A contiguous four-head contribution can place its first two source heads on the PLE participant and its next two on its matched remote storage owner. This gives source-order ownership `[PLE0, storage0, PLE1, storage1, …]` from the canonical domain order. Source-range order is independent of native communicator coordinate and GPU ordinal. The projection must authenticate both roles and their exact source range. The existing standalone fixed-head mode retains its original TP order.

For each source query, a PLE participant runs the original QFN Hash on its original DGO token/count/history authority. For its remote range, it packs only the actual assigned INT64 row IDs in token-major order. The paired storage owner receives those IDs, validates each against that head's source metadata, then loads only the corresponding immutable native row bytes. It returns those native rows to the PLE participant that owns the contribution. The local two heads and returned two heads form the four-head packet in token/global-head order. The four PLE consumers use their existing stage-local native `NativeAllGatherStage` and canonical fixed-head rank-major decode. Existing local validation and cohort agreement remain the device authority for the PLE query. The storage-only participant owns no lexical history, KV snapshot, model query, result consumer or duplicate n-gram source.

For `M` live rows and native row size `S`, each remote pair sends `M * 2 * sizeof(int64_t)` ID bytes and returns `M * 2 * S` native payload bytes, with the existing fixed native extent metadata per direction. The PLE collective sees four heads per contributing PLE GPU and only the four real output consumers. No full16-ID transfer, FP32 expansion on the remote path, all-eight result allgather or capacity padding is needed. M=0 sends only native metadata and leaves old destination payload untouched. A wide-to-scalar graph selection reuses admitted max storage with actual live extents and distinct graph identity.
