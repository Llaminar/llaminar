# CPU NativeQuantised expanded INT8 retirement: Phase A reachability audit

Audited at `6c7a490d669e19e4a54290f13b4ac9cd72aace57` on PR #73. Source references are to that revision (`git show <revision>:<path>`). This is a source audit, not a retirement or native-kernel qualification.

**No canonical production writer emits encoding 5, non-Q8 encoding 1, or the inline signed weight-sum plane. A production receive path is nevertheless live:** current packed-weight v9 accepts legacy layouts from incoming bytes. Encoding 5 can be materialized on receive but cannot become a sealed CPU projection. A supplied, well-formed non-Q8 encoding 1 can pass both the v9 receive gate and CPU publication, so its compensation consumer is **live on that input path**, even though no current production peer writer originates those bytes. Removal must close that boundary explicitly; it is not just a kernel dead-code deletion. Phase A stops here.

## Phase A validation

Two temporary Apple arm64 `clang++ -std=c++20 -Isrc/v2` probes used the production headers. The first executed the selector and footprint for all 22 source tuples: only Q8_0, Q8_1 and Q8_K returned 1; no tuple returned 5 or stored compensation; the explicit rotation flag would put compensation on exactly 19 non-Q8 tuples. The second exercised the real metadata seal: it admitted a compensated Q4_0-source value-1 unit and rejected a correctly sized IQ3_S value-5 unit with `Native CPU weight view encoding disagrees with original source`. The packed MPI receive-to-publication path is source-traced, not replayed end to end. No source/kernel edits, CTest, native profiling or WSL runs were needed for this audit.
